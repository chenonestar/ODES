# ODES · 线上民主测评系统

按仓库根目录的四份设计文档实现。单个 Go 可执行文件，无 CGO，
内含 Web 服务 + DHCP + DNS + 强制门户探测应答。

---

## 在开发机上跑起来

需要 Go 1.22+。

```bash
cd eval
go run ./cmd/eval -dev -seed
```

首次启动会让你设置管理员口令（≥10 位、含两类以上字符）。设完之后终端会打印：

```
作答端  https://127.0.0.1:8443   （测评网络可达）
管理端  https://127.0.0.1:8444/admin/   （仅本机可达）
```

浏览器打开管理端地址。**自签名证书会触发浏览器告警，点「高级 → 继续前往」即可**
——这正是文档反复强调的：正式测评必须用公共 CA 为自有域名签发的真实证书，
否则现场几百部手机每人都要点一次"继续访问"。

不想每次敲口令：

```bash
go run ./cmd/eval -dev -seed -password 'Test-Passw0rd'
```

### 常用参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `-dev` | 关 | 只绑回环、不启用 DHCP/DNS、强制自签名证书 |
| `-seed` | 关 | 生成一份演示项目（仅在库为空时执行） |
| `-config` | `config.toml` | 配置文件路径，不存在则用内置默认值 |
| `-data` | `data` | 数据目录 |
| `-port` | 配置值 | 覆盖 HTTPS 端口（管理端用 端口+1） |
| `-password` | — | 管理员口令，留空则交互式输入 |

`-dev` 只改三件事：监听地址、是否绑 53/67、证书模式。**其余行为与现场部署完全一致**
——没有"开发模式跳过校验"，否则调试通过不代表现场能用。

## 走一遍完整流程

`-seed` 生成的演示项目是「2026 年度 XX 单位领导班子民主测评」：
4 位测评对象 × 8 道题（德能勤绩廉 + 综合 + 评语），30 份令牌，应参加 30 人。

1. **打开项目** — 首页点项目名。页面上方是发布前置校验 PC-01~09，
   一开始 PC-06（令牌单已打印）和 PC-07（试填已完成）是 ✗。
2. **打印令牌单** — 点「打印令牌单」。30 张 A4，每张含 SSID、短码、URL。
   注意令牌**已随机重排**，打印顺序与名单顺序无关。
3. **试填验证** — 点「试填验证」，点任一试填链接，在作答页填一遍提交。
   试填数据进独立数据区，不计入统计，发布时清空。
4. **发布** — 前置校验全绿后点「发布测评」。校验不过会一次性列出**全部**
   未通过项，不是只报第一条。
5. **作答** — 从令牌单页面复制任一 URL（开发机上把 `localhost:8443` 换成
   `127.0.0.1:8443`），在浏览器打开。按测评对象逐页翻，字号三档可调，
   草稿存在 LocalStorage。同一令牌提交第二次会被拒。
6. **截止** — 点「手动截止」。这一步会执行 `wal_checkpoint(TRUNCATE)` + `VACUUM`，
   是匿名化的必需步骤，不是可选优化。
7. **看统计** — 四档票数、优秀率、称职以上率、加权得分。分母是**应参加人数**。
8. **导出** — 统计报告（HTML）、明细 CSV、原始匿名数据 CSV。
   连点两次原始数据导出，你会看到记录顺序和编号都变了——这是刻意设计。
9. **归档擦除** — 先下载加密归档包（记下 SHA 前 8 位），勾选确认、填入校验值，
   执行擦除。之后项目数据全部消失，只剩 `archive_meta` 里的核验编号。

## 跑测试

```bash
go test ./...            # 完整，约 15 秒
go test ./... -short     # 快速
go test ./internal/store -run AT01 -v   # 看时序不可还原的实测数据
```

几条值得单独看的：

| 用例 | 验的是什么 |
|---|---|
| `TestAT01_SubmissionOrderNotRecoverable` | 200 份提交后物理顺序与提交顺序的秩相关系数 |
| `TestAT01_ControlAutoIncrementLeaks` | 对照组：自增主键下 ρ = 1.0000，证明这条测试确实能发现问题 |
| `TestAT02_AnonymityInvariants` | WITHOUT ROWID / 无时间列 / 无跨表外键，对实际建好的库执行 PRAGMA |
| `TestST01_RateIdentityExhaustive` | 随机穷举 20000 组，四档 + 弃权 ≡ 100.0% |
| `TestTX01_ConcurrentSubmitSameToken` | 同一令牌并发 20 次提交，恰好 1 条落库 |
| `TestForeignKeysActuallyOn` | 连接级 foreign_keys 确实开着，级联删除真的会发生 |

## 现场部署

```bash
GOOS=windows GOARCH=amd64 go build -o eval.exe ./cmd/eval
```

拷贝 `eval.exe` + `config.toml` + `cert/` 到笔记本，网卡设静态 `192.168.66.1/24`，
然后直接运行。参照 `config.example.toml` 改配置。

Linux/macOS 绑 53/67/80 需要 root 或 `CAP_NET_BIND_SERVICE`；Windows 需要在
防火墙提示中放行。绑不上时程序不会退出，而是打印降级提示继续跑。

## 目录结构

```
cmd/eval/          入口、自检、优雅退出
internal/
  anon/            随机主键、令牌、短码、输出重排　★所有对外输出必经
  crypto/          KEK/DEK 双层密钥、AES-256-GCM 字段加密
  model/           领域实体　★匿名区两个结构体不得有时间字段
  store/           数据访问，手写 SQL，只做事务性读写不做聚合
  service/         业务编排　★唯一可以开启事务的层
  stats/           内存聚合管线　★全部口径规则的唯一归属地
  export/          CSV / HTML 报告
  wipe/            VACUUM + 覆写空闲空间 + 残留校验
  httpd/           路由装配，管理端与作答端分属两个监听器
  admin/           管理端服务端渲染
  evalui/          作答端自包含单页
  netsvc/          DHCP / DNS / 门户探测应答（由技术尖刺①移入）
  config/          config.toml 解析、证书装载与 CK-01~05
```

依赖方向：`admin / evalui → service → store / crypto / stats / anon`，反向依赖禁止。

## 与设计文档的偏差

以下是有意的取舍，都是为了让代码在开发机上 `go run` 就能跑起来，不需要额外工具链。
每条都不影响文档所述的架构约束。

| 文档选型 | 实际实现 | 原因 |
|---|---|---|
| chi | 标准库 `http.ServeMux` | Go 1.22+ 已支持方法与路径通配，路由语义相同，少一个依赖 |
| sqlc | 手写 SQL + `database/sql` | ADR-006 的真实意图是"不用 ORM、表结构显式定义"，手写 SQL 同样满足，且省掉代码生成步骤 |
| goose | 启动时执行内嵌 `schema.sql` | 目前只有一个版本，引入迁移框架为时尚早 |
| templ | `html/template` | 免去 templ 代码生成，`go run` 直接可跑 |
| htmx + Alpine.js | 原生 JS | 作答端本就要求零外部资源；管理端在回环上，交互简单 |
| Tailwind + daisyUI | 手写 CSS 并内嵌 | 免去 Node 工具链——这是"开发机上直接跑"影响最大的一条 |

第三方依赖只有两个：`modernc.org/sqlite`（CON-07 要求的纯 Go 驱动）和
`golang.org/x/crypto`（Argon2id）。加上 `golang.org/x/term` 用于口令输入不回显。

### 对文档判据的一处修正

LLD 11.1 的 AT-01 写的是「单次试验，判据 |ρ| < 0.15」。这个判据统计功效不足：
n = 200 时随机排列下 ρ 的标准差是 1/√199 ≈ 0.0709，0.15 只相当于 2.12 个标准差。
蒙特卡洛实测**单次试验有约 3.2% 的概率自然超过 0.15** —— 放进 CI 就是个每 30 次
构建红一次的 flaky 测试，而它红的时候并不代表匿名性出了问题。

实现改为跑 7 轮独立试验取 |ρ| 中位数（随机下约 0.048），并保留单轮 5σ 上限检查。
一旦真的退化成自增主键，每轮都会接近 1.0，中位数判据同样立刻触发。

## 几个不要动的地方

这些不是风格问题，改了会直接破坏匿名性承诺：

1. **`model.Token` 和 `model.AnswerRecord` 里不要加字段。**
   尤其不要加时间戳、序号、对方的 ID、`is_paper_entry`。
   `store.Open()` 启动时会断言，加了直接起不来。
2. **不要给 `LoadAnswers` 加 `ORDER BY`。** 读出顺序就该是物理顺序。
3. **对外输出记录集合之前必须 `anon.Shuffle`。** 统计、导出、评语列表、归档包，
   一个都不能漏。
4. **不要把 IP 写进任何持久化路径。** 限流用的 IP 只在内存里，进程退出即消失。
5. **进入「已截止」时的 `wal_checkpoint(TRUNCATE)` + `VACUUM` 不能省。**
   在这一步之前，WAL 里仍然按提交先后排着帧。
6. **提交事务里作答要写在令牌置位之前，且必须同事务。** 理由见 ADR-004 和
   `service.Submit` 的注释。
