本版修订说明

V2.1 补充变更：HTTPS 证书方案修正——原设想的公共通配域名服务无法完成证书签发流程，改为由考察部门使用自有域名、证书经外部签发后放入程序目录，系统只负责校验与到期提醒，不再提供"一键续签"。场景一的证书检查步骤、场景二的启动自检、两处检查清单与附录 FAQ 相应调整。

V2.0 的主要变更：部署形态由"接入被考察单位局域网"改为考察组自备独立测评网络（场景二重写）；发放机制由"匿名链接 + 通用验证码"两套并列改为一码三形态（场景一、二）；评分制由 1–10 分改为四档等级为主，并新增统计口径说明（场景四、附录）；归档改为导出加密包 + 本机擦除。各场景步骤与验收清单均标注版本A的需求编号，便于交叉核对。

01引言与背景

1.1 项目缘起

考察组到某单位考察干部，需要组织该单位干部职工进行民主测评。当前做法是：提前打印测评表、盖章、带到现场分发、参会人员纸质填写、投入票箱、开箱后人工逐张统计。整个过程耗时半天甚至一天，人工统计容易出错，纸质表存在笔迹辨识风险。

本系统的定位是：把一套可随身携带的装备——一台笔记本、一台交换机、几台无线接入点——变成移动测评工作站。考察组进入被考察单位后自行组建一个独立的测评网络，参会人员用手机扫码匿名完成测评，统计自动生成，测评结束即出报告，随后加密封存并擦除本机数据。

1.2 核心目标

目标说明
拎包即走系统为单个可执行文件，与网络装备一同装箱，现场 15–20 分钟完成部署
网络自持测评网络由考察组自备设备构成，不接互联网、不接被考察单位任何网络、不需要对方网管配合
真正匿名在不修改程序、不使用取证手段的前提下，任何人无法把一条作答记录关联到具体的人
口径可用产出的是优秀率、称职以上率这类可直接写入考察报告的指标，而不是无制度依据的平均分
扫码即答参评人员不下载 App、不注册账号、不输姓名，扫码即进入
用完即清测评结束导出加密归档包，随即擦除本机数据，笔记本不长期携带考察材料

1.3 系统边界

以下情形明确不由本系统承担，在业务确认时需一并说明：

  • 多地分散参评：下属单位、分支机构人员跨地参评，形态上属于另一个产品，不在本系统范围；
  • 互联网远程作答：系统全程离线，不提供任何公网通道；
  • 选举表决、记名投票：制度性质不同，不以本系统承载；
  • 长期历史数据比对：与"测评结束即擦除"的保密要求冲突，历史数据以离线加密包保存，系统内不提供比对；
  • 多台笔记本并行承载同一场测评：理由见版本A第 8.7 节。

1.4 阅读指引

场 景 一

出发前准备

考察组在办公室完成测评项目的全部准备工作，包括证书检查、测评表设计、令牌打印与试填验证。做好这一步，现场只剩部署与分发。

03场景一：出发前准备

3.1 装备与系统就位

  1. 取出装备箱装备箱内容：笔记本、冷备笔记本、交换机、无线接入点×4、网线、插排、UPS、配置卡、令牌单回收袋。全部设备由考察部门自备，不使用被考察单位提供的任何网络设备（版本A CON-01）。
  2. 启动系统双击可执行文件，系统自动启动服务并打开管理后台。无需安装数据库、无需配置运行时。首次使用时引导设置管理员密码（FR-SYS-010）。
    密码无找回机制，遗忘则数据不可访问。建议考察组两人分别知悉。
  3. 检查证书管理后台首页显示启动自检结果，其中证书一项须显示：域名匹配、在有效期内、剩余天数 ≥30 天。
    不满足时，须请信息化岗位重新签发并替换程序目录下的证书文件（系统不内置续签功能，FR-SYS-021 / 022）。
    两种情况都会导致现场每部手机弹安全警告：一是证书过期；二是证书本身有效，但签发时用的主机名与系统配置的域名不一致。后者更隐蔽，系统会在自检中直接指出。这是最容易被忽略、后果最严重的准备遗漏。

测评说明FR-PRJ-013展示给参评人员的须知与评价标准说明

截止时间FR-PRJ-0122026-08-10 11:30

填写完成后项目为草稿状态，可随时修改。若历史项目结构类似，可直接复制后调整（FR-PRJ-022）。

3.3 设计测评表

工作量最大的环节。多数情况下可直接调用内置的"德能勤绩廉"标准模板（FR-FRM-062，见 附录 8.1），仅替换测评对象即可。

  1. 添加测评对象录入本次被评价的领导干部姓名与职务，手动添加或 Excel 导入（FR-FRM-030）。
    可为其设置分组标签（如"班子成员""中层正职"），用于后期分组查看统计（FR-FRM-032）。
    注意：分组内对象少于 3 人时系统不展示该分组独立统计，以防通过小样本排除法推断个人意见。
  2. 添加题目四种主要题型：
    题型编号适用
    等级题
    干部测评首选    		FR-FRM-010优秀 / 称职 / 基本称职 / 不称职 + 弃权。这是干部考察测评的标准题型，产出的比率可直接写入考察报告
    打分题FR-FRM-0111–5 或 1–10 分。适用于满意度测评、专项工作评议，不建议用于干部考察测评，理由见 6.1
    单选题FR-FRM-012综合性判断题
    多选题FR-FRM-013如"该同志的突出优点（可多选）"
    开放评语FR-FRM-014具体意见与建议
    每题可设必填或选填。等级题与单选题必须提供"弃权"选项（FR-FRM-021）——这是纸质测评中"未表态"的电子对应物，是有效表达，与漏填区分统计。
  3. 组织题组按"德 / 能 / 勤 / 绩 / 廉"分块，或按"政治素质 / 业务能力 / 作风纪律"等其他方式分组，支持拖拽排序（FR-FRM-023）。
  4. 确认规模设计器实时显示展开后作答项总数 = 题目数 × 关联对象数（FR-FRM-034）。
    上限：题目 ≤50 道、测评对象 ≤20 人、展开后作答项 ≤400 个。
    举例：15 题 × 8 位班子成员 = 120 个作答项，参评人员在手机上约需 12–18 分钟完成。规模明显超出时应精简题目，而非指望参评人员有耐心。
  5. 预览以参评人员视角查看展示效果。作答页按测评对象逐页呈现（FR-FRM-033），每页只评一个人，不会出现几十行的大矩阵。

3.4 导入参评人员名单

  • 手动逐条添加或 Excel/CSV 批量导入（FR-TKN-010），导入前提供预览确认；
  • 名单只需一个标识（姓名或编号）；
  • 名单的作用仅有两个：确定生成多少个令牌，以及核定应参加人数。
关键设计：名单与作答之间不存在任何链路

导入名单时，系统不会把姓名或编号写入令牌表。令牌表只存三样东西：随机生成的令牌值、所属批次、是否已使用。"哪张令牌单给了谁"这件事只发生在管理员的物理分发动作中，系统对此一无所知。

名单在令牌单打印完成后可以整表删除，不影响系统运行与统计（FR-TKN-012）。

3.5 生成并打印令牌单

这是本版相对 V1.0 变化最大的环节。原来的"匿名链接"与"通用验证码"两套并列机制，合并为一个令牌、三种表示形态。

形态说明
URL完整链接，二维码的编码内容
二维码主用入口，扫码直达
8 位短码肉眼可读，扫码失败时手工输入。含校验位，输错即时提示

三者指向同一个令牌，任一形态使用后其余同时失效（FR-TKN-022）。一次印刷同时承载两条入口路径，不需要准备第二套凭据。

  1. 生成令牌系统按名单人数生成令牌，另按 10% 生成备用令牌单独装袋（FR-TKN-035）。
    若需分批测评，在此指定批次数与每批数量（FR-TKN-024）。
  2. 系统自动随机重排排版打印前，系统对令牌集合执行一次密码学随机重排（FR-TKN-025）。打印顺序与生成顺序、与名单顺序均无关。
    这一步是匿名性的第一道关口。若打印顺序即名单顺序，管理员只要留一份打印底稿，人码对应关系就完整可查——V1.0 的设计正是如此。
  3. 打印A4 纵向、一人一张，不需裁切。单页上有：测评名称、要连接的 WiFi 名称、大幅二维码（边长 ≥8cm）、8 位短码、操作须知、回收提示。单页上不出现任何人员姓名或序号（FR-TKN-026）。
    整页印刷免去了 200 次裁切，二维码和短码都能做得足够大——会场光线不佳、手机镜头老旧时的扫码失败，主要就来自二维码太小。须知直接印在单上，也省去引导人员反复解释。
  4. 按 WiFi 分袋令牌单上的 WiFi 名称（KCZ-EVAL-1 至 -4）用于把参评人员分流到不同的无线接入点。按 SSID 分装成四袋，现场随机分发。
    由于令牌单已随机重排，分流天然是随机的，不会出现"某个处室全在同一台设备上"的情况——这对匿名性有实质意义。
出发前就能把令牌单全部印好

二维码里含访问地址，而地址取决于笔记本的 IP。因为测评网络是考察组自备的、网段永久固定为 192.168.66.x，所以地址在出发前就是确定的，令牌单可以提前一周打印装袋。

这正是坚持自备网络设备的实际收益之一。若依赖被考察单位分配 IP，地址要到现场才知道，令牌单就只能现场打印——考察组要么背一台打印机，要么借用被考察单位的打印机打印测评二维码。

3.6 试填验证

系统为每个项目额外生成 3 个测试令牌，可反复使用不失效，数据不进统计、不计入提交数（FR-PRJ-030～033）。

  • 出发前用测试令牌完整走一遍作答流程，确认题目无误、必填设置合理、手机显示正常；
  • 试填也是现场组网验收的手段——到达会场后用测试令牌验证每台无线接入点是否可用，不消耗真令牌；
  • 发布时系统自动清空试填数据。

3.7 保存为模板

设计好的测评表可保存为模板（FR-FRM-060），下次创建同类测评直接调用，仅替换测评对象。模板不含任何人员与作答信息，不受"用完即清"约束，可长期保留跨考察复用。

场 景 二

到达考察单位与现场组网

考察组进入会场，用自带装备搭建一个独立的测评网络，验证连通后发布测评、分发令牌单。全程不需要被考察单位网管配合。

04场景二：到达与组网

4.1 测评网络是什么样的

考察组自带的笔记本、交换机和四台无线接入点，在会场组成一个独立的、不通互联网、也不接被考察单位任何网络的小型局域网。参评人员的手机连接这个网络的 WiFi 完成作答。

为什么设备必须考察组自备（版本A CON-01）

这不只是技术问题，更是程序问题。被考察单位是本次测评的利益相关方。由其提供承载测评数据的网络设备，等同于让被监督方提供监督工具：

  • 一旦测评结果产生争议，考察组没有任何可拿出来自证的独立证据；
  • 参评人员看到设备是本单位网管搬来架好的，只要会场里有一句"这网是咱们自己的"，匿名性的可信度就崩了——大家开始投安全票，结果全优、毫无区分度，这次考察等于白做。这个损害不需要任何人真的做坏事就会发生；
  • 设备配置不在我们手里，现场出问题只能等对方网管，而几十上百位干部正坐在会场等着。

整套网络装备约 2100 元，一次采购长期复用，摊到每场考察不过几十元。

唯一例外：单批参评超过 100 人且确实无法分批时，可借用被考察单位既有的企业级无线（大礼堂通常已有覆盖）。此时须执行行前对接清单，并由考察组负责人书面知悉残余风险。这是例外，不是可以因为省钱而选择的默认项。

4.2 现场部署（15–20 分钟）

  1. 供电与汇聚插排通电 → UPS 上电 → 交换机上电，确认指示灯正常。
    UPS 不是可有可无的：会场临时断电对纸质测评没影响，对本系统是灾难。
  2. 笔记本就位网线插入交换机，启动程序。管理后台首页显示启动自检结果（FR-NET-040）：网卡地址、端口绑定、证书（域名匹配与有效期），三项须全部为绿色。
    出发前已检查过一次，此处是复核——现场若因临时更换网段而改过配置，这一步会把不一致拦下来。
  3. 接入点上电四台 AP 依次上电，网线插入交换机。AP 这一侧的网线必须插 LAN 口，不能插 WAN 口。
    用手机扫描无线列表，确认 KCZ-EVAL-1 到 -4 四个信号全部可见。
    AP 的全部配置（工作模式、信道、SSID、关闭 DHCP）在出发前已完成并保存备份，现场不需要重新调试，只需上电插线。
  4. 布置位置四台 AP 分散在会场四角或按座区分布，不要堆在讲台旁。架高——挂墙、放高柜或桌面立起，避开桌下、金属柜后、纸箱堆。
    人体对 5GHz 信号吸收明显。空会议室实测很好看，坐满 50 人后后排会明显劣化，布置时要按坐满状态考虑。
  5. 连通验证用两部手机分别连接 AP1 和 AP4（覆盖信道两端），各扫一张测试令牌令牌单，完整走完"进入 → 填写 → 提交 → 完成页"。
    试填数据不进统计，可放心操作。这是验收现场网络是否可用的标准动作。
  6. 核对接入数管理后台首页显示实时接入终端数（FR-NET-041）。数字与实际连接的手机数一致，说明地址分配正常。
现场最高频的两个故障

其一：AP 网线误插 WAN 口。插 WAN 口会让这台 AP 变成路由器，自己开始分配地址，手机拿到错误的网关。症状是"WiFi 连上了但页面打不开"。

其二：某台 AP 的 DHCP 服务没关。症状完全相同，且随机出现——只有连到这台 AP 的人受影响。

排查方法：查看手机拿到的 IP 地址。正常应在 192.168.66.50 到 192.168.66.250 之间。若是别的网段（如 192.168.1.x），即为上述原因之一。

4.3 手机连上后提示"无法上网"是正常的

测评网络本来就不通互联网，手机连上后会做联网检测并发现失败。若不处理，后果很严重：

  • 安卓手机的"自动切换网络"默认开启，会主动切回移动数据——此后手机再也访问不到笔记本，参评人员看到的是打不开的页面；
  • 部分机型会弹出网络登录窗口，遮挡作答页面。

系统已内置应对机制（FR-NET-030）：对手机的联网检测请求做出应答，使其判定网络正常，不再切换。现场无需引导参评人员关闭移动数据——上百人逐个设置不具可行性。

若个别手机仍提示，可告知参评人员："提示不能上网是正常的，选择'仍然连接/保持连接'即可。"

4.4 发布测评

确认网络正常后，管理员点击"发布"。系统执行发布前置校验（FR-PRJ-023）：至少一个测评对象、至少一道题、时间合法、令牌已生成、试填已通过。任一不满足则禁止发布并明示原因。

  • 发布后状态变为"已发布"，到达开始时间自动转为"进行中"；
  • 发布后测评表结构与测评对象不可修改；
  • 已发布但尚无任何提交时，允许撤回发布回到草稿修改（FR-PRJ-025）。一旦有人提交则不可撤回。

4.5 分发令牌单与引导入会

  1. 随机分发按 WiFi 分袋的令牌单随机发放，不按座次、不按名单顺序、不按部门。同时在会场白板或大屏公布本场 WiFi 密码。
  2. 分排引导扫码不要统一号令"现在开始扫码"。按排引导，让几十台手机的连接过程自然错开到 5 分钟。
    开场同步入会是全场无线负载最重的时刻。这个峰值靠主持流程消解，比堆硬件有效得多。
  3. 不喊统一提交填完即交，自然错开提交峰值。
  4. 当场回收令牌单散会时全部令牌单当场回收（含未使用的），集中销毁。
    令牌单留在桌上或纸篓里是很常见的。持有一张令牌单即持有一个令牌，若有人在链路上留存了数据，就可能反查这张令牌单主人的作答。回收这一步不花钱，但缺了就是个洞。

05场景三：测评进行中

5.1 参评人员的作答流程

  1. 连接 WiFi按令牌单上印的名称连接（如 KCZ-EVAL-2），输入公示的密码。
  2. 扫码进入用手机扫描令牌单上的二维码，浏览器打开作答页面。
    扫码失败时，打开浏览器访问令牌单上的短码入口地址，输入 8 位短码进入（FR-ANS-010）。
    页面不显示任何个人信息，不要求登录、不要求输姓名。
  3. 阅读说明页面顶部展示测评说明与评价标准。
  4. 逐位评价每页只评一位测评对象（FR-FRM-033），页面顶部显示"第 2/5 位　已完成 18/75"。
    等级题为四档大按钮 + 弃权，整行可点，不需要精确点小圆点。必填题标星号。
    右上角可切换字号，三档可调（FR-ANS-021）。
  5. 提交点击提交 → 系统检查必填项，未完成则高亮并滚动定位到第一处 → 弹出确认框"提交后将无法修改，确定提交？" → 确认后提交 → 显示"感谢参与"完成页。
  6. 提交后该令牌立即失效。再次访问显示"您已完成测评，感谢参与"。
    系统同时清除手机本地的草稿（FR-ANS-016），不会把内容留在手机上。
关于草稿与借用手机

填写过程中系统会在手机本地暂存草稿，按令牌分别存放（FR-ANS-015）。这意味着两个人先后用同一部手机作答不会互相串档；提交后草稿立即清除，也不会把上一个人的内容留给下一个人看到。

5.5 纸质密封补录

不在场人员的处理办法，沿用纸质时代的成熟做法（FR-ANS-090）：

  1. 发放纸质测评表，本人填写后密封信封交回；
  2. 由考察组两人共同拆封，一人念、一人录入系统；
  3. 录入界面须勾选确认「双人当场拆封、内容已双人核对」并填写复核人姓名，系统记入操作日志（份数、复核人、时间，不含作答内容）；
  4. 录完后纸质原件由两人签字，装回密封袋随考察材料归档；
  5. 补录记录与在线记录合并统计，数据中不可区分；
  6. 补录份数在统计概要与正式报告中单独标注，如"共 187 份，其中纸质补录 6 份"。

这一环节的匿名性由工作程序保障，不由技术保障。这是可接受的——它与纸质测评的保障强度相同。

测评结束与归档

06场景四：结束与归档

6.1 截止与汇总

  • 自动截止：到达截止时间自动关闭提交通道；
  • 手动关闭：所有人提交完毕后管理员可提前关闭（FR-PRJ-024）；
  • 自动汇总：截止后统计秒级完成（200 人 × 200 作答项，<1 秒）。

6.2 为什么用四档等级而不是打分

V1.0 的示例测评表全部用 1–10 分制。本版改为四档等级为主，这是本次修订中影响最大的业务变更，理由需要向业务方说明清楚：

对比维度四档等级1–10 分
能否进考察报告优秀 / 称职 / 基本称职 / 不称职直接对应年度考核法定等次。报告里写"张三同志优秀率 92.3%，称职以上率 100%，无不称职票"是标准表述"张三同志平均分 8.6 分"在公文里没有制度依据，上级看不懂，也无法与其他单位横向比较
不同人打分是否可比四档有明确文字锚点，理解趋同有人从不给 10 分，有人普遍给 9 分。同一个"8 分"在不同人手里含义完全不同
精度是否真实不产生虚假精度平均分 8.6 与 8.5 的差异在统计上没有意义，但一旦印在报告上就会被当作排名依据过度解读
手机上好不好点4–5 个大按钮，年长干部友好10 个选项在手机上密集难点
区分度较低。三人同为"优秀率 95%"时难以排序 → 由加权得分辅助解决（见 6.4）较高

打分制并未删除，保留用于满意度测评、专项工作评议等确实使用分数的场景。

6.3 统计口径（最需要业务确认的一节）

为什么必须先把口径定死

同一批作答数据，分母取"应到人数"还是"实到人数"，能算出两个差异显著的"优秀率"。口径不明是测评结论最容易被质疑的地方。本系统把口径固化为系统行为，并随报告一同输出，避免事后争议。

分母：默认取应参加人数

6.4 加权得分：只用于排序，不用于结论

四档制的短板是区分度低——三位测评对象同为"优秀率 95%"时无法排序。系统提供加权得分作为补充：

  • 默认赋分：优秀 100 / 称职 80 / 基本称职 60 / 不称职 0，赋分可在测评表中配置；
  • 加权得分 = Σ（各档票数 × 档位赋分）÷ 有效票数，弃权不计入分子分母；
  • 界面与报告中以次要样式呈现，标注为"辅助排序指标"，不作为结论表述。

结论仍然写比率。加权得分只在需要内部排序时参考。

6.7 留痕、归档与擦除

干部考察工作通常要求测评原始材料留存备查。电子化后的对应做法：

  1. 导出并打印导出原始匿名数据与正式统计报告 PDF，全部打印。
  2. 签字封存两份材料由考察组两名以上成员签字，装入密封袋，按考察材料管理规定归档。这是电子测评的纸质留痕环节，不可省略。
  3. 加密归档导出加密归档包，口令由管理员单独设定（与登录密码不同），保存至指定介质。介质与纸质材料分别保管。
  4. 本机安全擦除确认归档包已保存后，系统执行：删除项目全部记录 → 重建数据库文件 → 覆写原文件所占空间 → 校验残留（FR-SYS-031）。
    擦除前须二次确认并勾选"已确认加密归档包已保存至指定介质"。
    单纯删除后 SQLite 文件里的数据仍可被恢复工具还原。涉及干部考察材料，必须做安全擦除。
  5. 项目转为已归档列表中仅保留元信息记录，作答数据已不在本机。

7.1 匿名性保障（最高优先级）

承诺边界（本版修订）

V1.0 承诺"即使管理员看数据库也无法关联"。这个承诺无法兑现，也无法验收——管理员物理持有笔记本，可以修改程序、抓取内存、读取文件残留，还可以在会场直接观察谁先交谁后交。

本版承诺：在不修改程序、不使用取证手段的前提下，管理员通过系统界面、数据库文件、日志和全部导出文件，无法把任何一条作答记录关联到具体的人。超出这个边界的防护，由工作程序承担（双人在场、设备封存、令牌单回收）。

这个降级不是退让，而是把承诺改成可以被验收、也可以对参评人员诚实说明的形式。

要求说明
两表物理隔离令牌表与作答记录表之间无外键、无任何可连接字段
切断时序通道两表主键均为随机值、均不存时间、输出顺序每次随机重排、物理写入顺序打散。这是本版最重要的修复，见下
令牌与人无算法关联令牌由密码学随机数生成，不从人员信息推导
不记录分发轨迹系统不存"哪个令牌发给谁"；令牌单打印前已随机重排
IP 与 MAC 不落地IP 仅在内存限流窗口中使用；地址分配记录仅在内存；日志、数据库、导出文件中均不出现
小样本保护分组统计不足 3 人时不展示
令牌单当场回收由操作规程保障
V1.0 的关键缺陷：顺序会出卖一切

V1.0 中作答记录用自增编号（R001、R002……），令牌表记录使用时间。两张表虽然"没有外键"，但插入顺序天然一一对应——第 N 个被使用的令牌，就是第 N 条作答记录。把两张表各自按顺序排出来并排一看，人码映射完整还原。再结合管理员在会场对提交先后的直接观察，V1.0 的匿名性在实践中根本不成立。

V1.0 提出的"时间戳模糊到分钟"解决不了问题：100 人测评通常 15 分钟内交完，分钟级精度下每分钟只有几个人；而且时序通道的根源是顺序不是精度，降低精度不改变顺序信息。本版直接取消时间存储，并同时改用随机主键、输出随机重排、物理写入打散——四项措施须同时实施，缺一无效。

怎么验证匿名性达标

  • 审计测试：组织 10 人以上完成一次完整测评，其中 3 名测试人员的答案事先由第三方记录。测评后由管理员在不修改程序的前提下，尝试从数据库、日志、全部导出文件中推断这 3 人的答案。准确率不高于随机猜测则达标；
  • 时序专项测试：3 名测试人员按指定顺序提交（第 1、第 5、第 9 位）。审计者获知该顺序信息后仍无法定位对应记录，方为通过；
  • 残留检查：擦除后用文件恢复工具扫描，不应恢复出任何作答内容明文。

测试结果可在测评会前向参评人员说明，有助于缓解"大家不相信匿名"这一最现实的风险。

7.2 安全性

安全项措施
传输加密测评端强制 HTTPS，使用考察部门自有域名的公共 CA 证书，手机端无任何告警。不接受自签名证书——上百部手机逐一点"继续访问"不具可行性，且严重损害参评人员的信任
防篡改HTTPS 的首要目的是防止在途篡改，而不是防偷看。作答内容若能被链路上的第三方静默改写，测评结果的真实性就不存在了，而这种篡改无声无痕、事后无法发现
存储加密应用层字段加密：作答内容、评语、姓名、名单等敏感字段以密文存储，密钥由管理员口令派生，不落盘。主要防护场景是笔记本失窃
管理端隔离管理后台仅能在笔记本本机访问，测评网络中不可达
防重复提交令牌一次有效，提交事务内原子置位
口令与会话密码强度要求、5 次失败锁定、会话超时可配置（现场监控场景可调长）
无线加密WPA2-PSK，密码每场更换

8.3 常见问题

问题答复
为什么不能用被考察单位的网络设备？核心不是技术问题而是程序问题：由被监督方提供承载测评数据的设备，一旦结果产生争议，考察组没有任何可自证的独立证据；而且只要会场里流传一句"这网是他们自己的"，大家就会开始投安全票，结果全优、毫无区分度。装备约 2100 元一次采购长期复用，摊到每场几十元。
为什么不能在外网使用？限定局域网内访问是为了保障匿名性与保密。干部考察数据走公网会带来数据泄露与被攻击的风险，且多数单位的保密规定通不过。测评本来就是线下会议场景，独立局域网完全满足需求。
手机提示"此 WLAN 不可上网"？正常现象，测评网络本来就不通互联网。系统已内置应对机制，手机不会自动切回移动数据。若个别手机仍提示，选择"仍然连接"即可。
笔记本断电或死机会丢数据吗？UPS 可维持 30 分钟以上；数据库使用 WAL 模式，已提交数据不会丢失；硬件故障则由冷备笔记本接管，已提交数据最多损失 5 分钟。未提交的草稿会丢失，需重新作答。
200 人能同时测评吗？四台接入点可支撑单批约 200 人同时作答。超过 200 人建议分批——系统支持令牌按批开放，400 人分两批，每批约 15 分钟。会议本身通常也是分场进行的。
能不能多带几台笔记本分担？不能，也没有意义。瓶颈在无线信道而不在笔记本——一台笔记本处理 200 人的提交只占用个位数的 CPU。扩容的正确做法是增加接入点。而且多台笔记本会按部门分流，每台机器的数据就成了"某几个处室的作答"，反而制造出匿名性缺口。第二台笔记本的正确用途是冷备。
测评对象临时变动？发布前可随时修改。已发布但无人提交时可撤回发布。已有提交则不可修改，需关闭后复制为新项目。
有人当天出差不在？时间窗可放宽至当日，允许当天返回者补测；确不能到场者填纸质表，由考察组两人共同拆封、一人念一人录。跨地远程参评不在系统范围。
参评人员没有智能手机？可用电脑浏览器；或借用他人手机（草稿按令牌分开存放，不串档，提交后自动清除）；或使用考察组备用平板；或填纸质表由双人密封补录。
能同时进行多场测评吗？系统支持管理多个项目，但建议同一时段只开放一个，避免参评人员混淆。
为什么系统要用一个域名？直接用 IP 地址不行吗？不行。手机浏览器只信任"证书上的域名与地址栏一致"的站点，而公共机构不会为 192.168.66.1 这类私有 IP 签发证书。若改用自签名证书，每部手机都会弹出全屏安全警告——上百人现场逐一点"继续访问"既不现实，也会让大家对系统的可信度产生怀疑。因此需要考察部门注册一个域名（或用现有政务域名的子域），把它指向 192.168.66.1，再为这个域名申请正规证书。现场仍然完全离线：域名解析由笔记本自己完成，不需要连互联网。
证书是谁负责办的？多久办一次？由信息化岗位办理，考察组只负责在出发前检查。多数情况下可以做到全自动、不用人管——关键看这个域名的 DNS 能否给出 API 密钥，或能否加一条一次性的委托记录；两者任一可行，续签就由办公室的机器自动完成。只有在两条路都走不通、每次都要走工单时，才建议采购一年期商业证书，把一年四次的跨部门协调降为一年一次。系统会在证书剩余 21 天时持续提醒。
域名续费和证书续期是一回事吗？是两件事，不能混同。证书过期，手机会弹安全警告；域名过期更致命——解析直接失效，整套系统用不了。建议把两者的续费日期设为同一天、记入同一个提醒，由信息化岗位统一管理。
怎么向参评人员说明匿名性？可说明三点：一是令牌单随机发放，系统不知道哪张给了谁；二是系统不记录提交时间与顺序，无法通过先后推断；三是网络设备全部是考察组自带的，数据不经过本单位任何设备。审计测试的结果也可一并说明。
