# ODES · 线上民主测评系统

按仓库根目录的四份设计文档实现。单个 Go 可执行文件，无 CGO，
内含 Web 服务 + DHCP + DNS + 强制门户探测应答。

---

> `.gitignore` 里的运行时产物模式现在一律带前导 `/`。不带的话，为忽略
> 构建出来的 `eval` 可执行文件而写的一行 `eval`，会连 `cmd/eval/` 这个
> **目录**一起吞掉，于是整个程序入口从未进过仓库——克隆下来根本编译不出来。

## 在开发机上跑起来

需要 Go 1.22+。

```bash
cd eval
go run ./cmd/eval -dev -seed
```

首次启动会让你设置管理员口令（≥10 位、含两类以上字符）。设完之后终端会打印：

```
作答端  https://127.0.0.1:8443   （测评网络可达）
管理端  https://127.0.0.1:8444/admin/   （仅本机可达）
```

浏览器打开管理端地址。**自签名证书会触发浏览器告警，点「高级 → 继续前往」即可**
——这正是文档反复强调的：正式测评必须用公共 CA 为自有域名签发的真实证书，
否则现场几百部手机每人都要点一次"继续访问"。

不想每次敲口令：

```bash
go run ./cmd/eval -dev -seed -password 'Test-Passw0rd'
```

### 常用参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `-dev` | 关 | 只绑回环、不启用 DHCP/DNS、强制自签名证书 |
| `-seed` | 关 | 生成一份演示项目（仅在库为空时执行） |
| `-config` | `config.toml` | 配置文件路径，不存在则用内置默认值 |
| `-data` | `data` | 数据目录 |
| `-port` | 配置值 | 覆盖 HTTPS 端口（管理端用 端口+1） |
| `-password` | — | 管理员口令，留空则交互式输入 |

`-dev` 只改三件事：监听地址、是否绑 53/67、证书模式。**其余行为与现场部署完全一致**
——没有"开发模式跳过校验"，否则调试通过不代表现场能用。

## 走一遍完整流程

`-seed` 生成的演示项目是「2026 年度 XX 单位领导班子民主测评」：
4 位测评对象 × 8 道题（德能勤绩廉 + 综合 + 评语），30 份令牌，应参加 30 人。

0. **新建项目** — 首页点「新建测评项目」，填名称、时间窗与应参加人数，
   保存后直接进入测评表设计器：加测评对象、加题、拖拽排序、导名单。
   演示项目可以跳过这步。
1. **打开项目** — 首页点项目名。页面上方是发布前置校验 PC-01~09，
   一开始 PC-06（令牌单已打印）和 PC-07（试填已完成）是 ✗。
2. **打印令牌单** — 点「打印令牌单」。30 张 A4，每张含 SSID、短码、URL。
   注意令牌**已随机重排**，打印顺序与名单顺序无关。
3. **试填验证** — 点「试填验证」，点任一试填链接，在作答页填一遍提交。
   试填数据进独立数据区，不计入统计，发布时清空。
4. **发布** — 前置校验全绿后点「发布测评」。校验不过会一次性列出**全部**
   未通过项，不是只报第一条。
5. **作答** — 从令牌单页面复制任一 URL（开发机上把 `localhost:8443` 换成
   `127.0.0.1:8443`），在浏览器打开。按测评对象逐页翻，字号三档可调，
   草稿存在 LocalStorage。同一令牌提交第二次会被拒。
6. **截止** — 点「手动截止」。这一步会执行 `wal_checkpoint(TRUNCATE)` + `VACUUM`，
   是匿名化的必需步骤，不是可选优化。
7. **看统计** — 四档票数、优秀率、称职以上率、加权得分。分母是**应参加人数**。
8. **导出** — 统计报告 PDF / HTML、明细 xlsx / CSV、原始匿名数据 xlsx / CSV。
   连点两次原始数据导出，你会看到记录顺序和编号都变了——这是刻意设计。

9. **归档擦除** — 先下载加密归档包（记下 SHA 前 8 位），勾选确认、填入校验值，
   执行擦除。之后项目数据全部消失，只剩 `archive_meta` 里的核验编号。

## 跑测试

```bash
go test ./...            # 完整，约 15 秒
go test ./... -short     # 快速
go test ./internal/store -run AT01 -v   # 看时序不可还原的实测数据
```

几条值得单独看的：

| 用例 | 验的是什么 |
|---|---|
| `TestAT01_SubmissionOrderNotRecoverable` | 200 份提交后物理顺序与提交顺序的秩相关系数 |
| `TestAT01_ControlAutoIncrementLeaks` | 对照组：自增主键下 ρ = 1.0000，证明这条测试确实能发现问题 |
| `TestAT02_AnonymityInvariants` | WITHOUT ROWID / 无时间列 / 无跨表外键，对实际建好的库执行 PRAGMA |
| `TestST01_RateIdentityExhaustive` | 随机穷举 20000 组，四档 + 弃权 ≡ 100.0% |
| `TestTX01_ConcurrentSubmitSameToken` | 同一令牌并发 20 次提交，恰好 1 条落库 |
| `TestForeignKeysActuallyOn` | 连接级 foreign_keys 确实开着，级联删除真的会发生 |
| `TestDependencyDirection` | 分层依赖方向，反向 import 直接编译期外失败 |
| `TestShuffleBeforeOutput` | 每个对外输出点都调了 `anon.Shuffle` |
| `TestAnonZoneModelHasNoForbiddenFields` | 匿名区结构体没有时间/序号/对侧 ID 字段 |
| `TestChallengeInsteadOfHardReject` | 超阈值返回 428 + 算术题，而不是 429 |
| `TestArchivePasswordMustDifferFromLogin` | 归档口令与登录口令相同时拒绝出包 |
| `TestAdvancerPublishedReachesClosed` | 发布之后一定还能走到 closed，否则拿不到结果 |
| `TestAdvancerCatchesUpAcrossTwoLevels` | 关机跨过整个时间窗，开机一次推进直达 closed |

后三张表里的架构测试都做过"注入违规必须变红"的反向验证：给
`model.AnswerRecord` 加一个时间字段、让 `store` import `service`，
对应用例确实立刻失败。只会变绿的测试等于没有测试。

## 现场部署

```bash
GOOS=windows GOARCH=amd64 go build -o eval.exe ./cmd/eval
```

拷贝 `eval.exe` + `config.toml` + `cert/` 到笔记本，网卡设静态 `192.168.66.1/24`，
然后直接运行。参照 `config.example.toml` 改配置。

Linux/macOS 绑 53/67/80 需要 root 或 `CAP_NET_BIND_SERVICE`；Windows 需要在
防火墙提示中放行。绑不上时程序不会退出，而是打印降级提示继续跑。

### 项目管理与测评表设计（FR-PRJ-020~022 / FR-FRM-020~034 / FR-TKN-010~012）

管理端现在可以完整地建一场测评，不再需要 `-seed` 或改代码：

| 能力 | 说明 |
|---|---|
| 项目 CRUD | 新建 / 编辑 / 删除；**复制为新项目**只复制结构，不带作答数据、令牌与名单 |
| 测评对象 | 增删改、分组标签、拖拽排序 |
| 题组与题目 | 五种题型、必填选填、说明文字、拖拽排序、跨组移动 |
| 关联对象 | 指定子集或「全部」，勾「全部」在保存的当下展开为具体名单并冻结 |
| 实时计数 | 对象数 / 题目数 / 展开后作答项，三个上限就地显示（FR-FRM-034） |
| 名单导入 | .xlsx / .csv / 纯文本，**先预览后写入**，整表替换；可随时删除 |

三条设计上的取舍：

- **编辑只在草稿态开放。** 已发布之后改题，等于让不同的人答的不是同一张
  表——先答的人看到 8 道题、后答的人看到 9 道，统计分母对不上，而这件事
  事后从数据上完全看不出来。闸门在服务层，处理器绕不过去，有一条用例
  逐个方法验证这 15 个入口全都被挡住。
- **排序接口收完整顺序，不收"上移一位"。** 拖拽产生的本来就是一个新顺序；
  整体覆盖是幂等的，重发一次结果相同，而增量接口一旦丢包，顺序就错乱且
  事后无从发现。
- **名单与令牌之间不存在任何字段关联**（FR-TKN-011）。`roster` 只有
  id / project_id / label_enc 三列，有一条用例直接查 `pragma_table_info`
  守着——这条一旦被"顺手加个 token_id 方便核对"破坏，谁拿到哪个令牌就成了
  库里的明账。

拖拽用原生 HTML5 drag&drop，不引第三方库（LLD 12.7.4「能用原生工具时不叠
兼容层」）。

### 二维码（FR-TKN-032 / FR-TKN-033）

令牌单上是真二维码，`skip2/go-qrcode` 本地生成、不调任何外部服务。
内联为 data URI 而不是另开 `/qr?token=...` 端点——后者会让令牌值出现在
几十上百条请求 URL 里，留在浏览器历史与访问日志中。

打印样式此前**完全缺失**：`no-print`、`.sheet` 这些类在模板里用了但从未
定义过，打印出来会连管理端导航、提示框、按钮一起印上，也不保证一人一张。
现已补齐，并把 LLD 4.3 的三条硬要求写进 CSS：A4 纵向一人一张、二维码边长
≥8cm、短码 ≥36pt。浏览器实测 8.0cm / 40.0pt，二维码用 jsQR 解码后与令牌单
上印的 URL 逐字相符。

### Excel 导出（FR-EXP-011 / FR-EXP-012 / FR-TKN-034）

`excelize`，按 HLD 2.1 的选型。三个出口：

| 导出 | 内容 |
|---|---|
| 明细 xlsx | 按题型分 Sheet：测评概况 / 等级题 / 打分题 / 选择题 / 评语汇总 |
| 原始数据 xlsx | 与 CSV 同源同规则，导出前重排、编号现场生成 |
| 令牌清单 xlsx | 只有短码与 AP 序号，**不含任何人员信息、也不含令牌值** |

CSV 一并保留：政务机器上 Excel 版本参差，xlsx 偶尔打不开，而散会后取不出
数据是不可接受的。两者数据同源，列序也逐列对齐（有用例守着）。

### PDF 报告（ADR-009）

`gopdf` + 内嵌完整中文字库，含口径说明页（FR-EXP-020）与每页页脚核验编号
（FR-EXP-021）。字体 `web/fonts/report.ttf` **已随仓库提交**（Noto Serif CJK SC
转 glyf，SIL OFL 1.1，许可全文在同目录），克隆下来直接能出 PDF。
若换成不合格的字体，导出会给出可照做的提示并拒绝出报告，
HTML / xlsx / CSV 三个出口不受影响。

两件在实现过程中查证出来、文档里没写的事：

1. **gopdf 只认 glyf 轮廓的单体 `.ttf`。** 不支持 CFF 轮廓，也不解析
   `.ttc` 字体集合——而思源宋体与 Noto Serif CJK 的官方发布恰好两条都占。
   照 ADR-009 的字面直接放思源宋体 `.otf` 会加载失败。
   解法是转一次格式：OFL 明确允许，脚本在 `tools/otf2ttf/`，办公室机器上
   跑一次约 2 分钟。转换后实测 GB2312 与 CJK 基本区、扩展 A 全部 100%
   覆盖，54 个生僻姓名样本无一缺失。候选对比见 `web/fonts/README.md`。
   `go run ./tools/checkfont <文件>` 可当场自查手上这份是哪一种。
2. **gopdf 遇到字库里没有的字是直接丢掉**：不报错、不画方框，报告上只是
   少几个字。实测用日文字库排中文报告，"测评项目"会印成"目"、"统计报告"
   印成"告"，而拿到报告的人只会以为是打印机的问题。姓名少一个字的正式
   报告会被原样上报，没有任何人能发现。

   因此排版**之前**先做一次字形覆盖检查，缺字即拒绝出报告并列出缺了哪些字。
   检查基于实际要打印的内容而不是常用字表——出问题的恰恰是姓名里的生僻字，
   它们按定义不在常用表里。

### 超阈值时的算术验证（FR-ANS-032）

提交端点超过频率阈值时返回 **428** 与一道一位数加法题，而不是一刀切的 429：

```json
{"ok":false,"code":"CHALLENGE","challenge":"<id>","question":"7 + 4 = ?"}
```

作答端弹输入框，带 `X-Odes-Challenge` / `X-Odes-Answer` 两个请求头重试一次。
挑战本地生成、只存内存、一次性消费（答对答错都作废），不调任何外部验证码服务。

这条不是形式主义：测评网络里"无手机者借用他人手机"是预期场景，
同一 IP 连续提交数次很正常，而这些人散会后无法补测——直接 429 挡住就是数据丢失。

客户端最多重试 3 次，第二次起提示「答案不对，请重答」，超过则给出可继续的
出口提示并保留已填内容。**不能无限递归**：服务端每次答错都换一道新题，
参评人员会被一串永远弹不完的对话框困住，而且没有一处告诉他上次答错了——
他只会以为系统坏了。这条路径上的每个死循环都是真实的数据丢失。

### 已补齐的文档条款

审计中发现"实现比文档少做了"的条款，现已逐条补上：

| 条款 | 补了什么 |
|---|---|
| 等级档位可配 | 档数不再写死为 4，从 `question.config.grades` 读，允许 3~5 档 |
| 状态机 | 删掉 `published → closed` 这条 LLD 7.1 里本来就没有的迁移 |
| PC-09 | 证书可用性判据独立成 `config.Status.Usable()`（剩余 ≥1 天），与 CK-04 的 ≥21 天区分开 |
| PC-08a / PC-08b | 除总项数 ≤400 外，另限对象 ≤20、题目 ≤50 |
| FR-SYS-030 | 归档口令与登录口令相同时直接拒绝出包——两者分开保管才有意义 |
| 口径运算 | 比率全程整数定点（单位 0.1%），恒等式改为 `== 1000` 精确比较，不再有浮点容差 |
| FR-SYS-010 | 登录锁定写入 `meta.login_lock_until`，重启进程不能绕过 15 分钟锁 |
| LLD 7.1 推进器 | 从 `cmd/eval` 的 ticker 移进服务层 `Service.Advance`，幂等、可测、启动即先推一次 |

后一条是删掉 `published → closed` 之后才暴露出来的：迁移表里本来就没有
这条边，而「手动截止」按钮在 `published` 状态下照画不误，点下去只会得到
一页"不允许的状态迁移"。此时项目既截不了止，也就出不了统计、归档、擦除——
现场表现为散会后拿不到结果，且无补救手段。现在按钮只在 `running` 下出现，
`published → running` 由推进器负责，并有 5 条用例守着"发布之后一定还能走到
closed"这个可达性。

### 对文档判据的两处修正

LLD 11.1 的 AT-01 写的是「单次试验，判据 |ρ| < 0.15」。这个判据统计功效不足：
n = 200 时随机排列下 ρ 的标准差是 1/√199 ≈ 0.0709，0.15 只相当于 2.12 个标准差。
蒙特卡洛实测**单次试验有约 3.2% 的概率自然超过 0.15** —— 放进 CI 就是个每 30 次
构建红一次的 flaky 测试，而它红的时候并不代表匿名性出了问题。

实现改为跑 7 轮独立试验取 |ρ| 中位数（随机下约 0.048），并保留单轮 5σ 上限检查。
一旦真的退化成自增主键，每轮都会接近 1.0，中位数判据同样立刻触发。

另一处在 LLD 12.3：短码字符集刻意去掉了易混字符（0/O、1/I/L），只剩 31 个字符，
但那段示例代码写的是标准 Base32 编码——32 进制编不出 31 个字符的字符集。
实现改为逐字符随机取，不走 Base32。两处修正都已写回 LLD V1.2。

## 几个不要动的地方

这些不是风格问题，改了会直接破坏匿名性承诺：

1. **`model.Token` 和 `model.AnswerRecord` 里不要加字段。**
   尤其不要加时间戳、序号、对方的 ID、`is_paper_entry`。
   `store.Open()` 启动时会断言，加了直接起不来。
2. **不要给 `LoadAnswers` 加 `ORDER BY`。** 读出顺序就该是物理顺序。
3. **对外输出记录集合之前必须 `anon.Shuffle`。** 统计、导出、评语列表、归档包，
   一个都不能漏。
4. **不要把 IP 写进任何持久化路径。** 限流用的 IP 只在内存里，进程退出即消失。
5. **进入「已截止」时的 `wal_checkpoint(TRUNCATE)` + `VACUUM` 不能省。**
   在这一步之前，WAL 里仍然按提交先后排着帧。
6. **提交事务里作答要写在令牌置位之前，且必须同事务。** 理由见 ADR-004 和
   `service.Submit` 的注释。
